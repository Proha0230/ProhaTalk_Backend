# Версия 0.9

## Изменения

1. Реализован функционал Web Push-уведомлений.

   - подписка устройства на push-уведомления

   - отписка устройства от push-уведомлений

   - инициализация VAPID-ключей через библиотеку `web-push`

   - сохранение подписок в таблице `push_subscriptions`

   - отправка тестовых push-уведомлений авторизованному пользователю

   - автоматическое удаление недействительных подписок при ошибках `404` и `410`

2. Проведена миграция БД:

   - добавлена таблица `push_subscriptions` для хранения endpoint и ключей устройств

   - настроена связь подписок с пользователями (`CASCADE` при удалении пользователя)

3. Реализован поиск пользователей:

   - поиск по логину и имени через параметр `uLON`

   - при пустом значении возвращается полный список пользователей

4. Добавлена курсорная пагинация истории сообщений в чатах.

   - за один запрос отдаётся не более 20 сообщений

   - в ответе возвращаются флаги `hasMore` и `nextCursor`

   - через `cursor` можно дозагружать более старые сообщения

# Версия 0.8

## Изменения

1. Реализована полноценная работа с голосовыми сообщениями.

   - приём голосовых сообщений от клиентов

   - сохранение голосовых сообщений в базе данных (SSD-хранилище)

   - потоковая передача (stream) голосовых сообщений на frontend

   - валидация типа загружаемого аудиофайла

   - валидация максимально допустимого размера голосового сообщения

   Весь процесс интегрирован с WebSocket и обеспечивает мгновенную доставку голосовых сообщений пользователям.

2. Реализованы новые API для работы с заявками в контакты.

   - получение карточки пользователя, отправившего заявку на добавление в контакты

   - получение карточки пользователя, которому была отправлена заявка на добавление в контакты

3. Изменена архитектура объекта сообщения в истории чатов.

   Теперь каждое сообщение содержит явный тип контента:

   - `isText`

   - `isPicture`

   - `isAudio`

   Новая структура упрощает обработку различных типов сообщений и обеспечивает масштабируемость системы обмена сообщениями.

4. Проведена оптимизация внутренней логики обработки сообщений и медиафайлов.

5. Подготовлена архитектурная база для реализации обмена изображениями между пользователями.

   В следующих версиях будет добавлена возможность отправки и получения изображений в чатах.

# Версия 0.7

## Изменения

1. Полностью реализовано API для работы с аватарами пользователей:

   - получение аватара
   - изменение аватара
   - удаление аватара

2. Проведена миграция БД:

   - в таблицу пользователей добавлен столбец для хранения информации об аватаре

3. Реализован алгоритм обработки и хранения изображений:

   - получение изображения с клиента через `File`
   - компрессия изображения с помощью библиотеки `Sharp`
   - конвертация в формат `.webp`
   - сохранение качества на уровне 85%
   - сохранение файлов на локальном SSD-сервере
   - генерация уникального имени файла через `randomUUID` из библиотеки `crypto`

4. Реализован безопасный механизм получения изображений пользователей с сервера.

5. Настроено production-окружение:

   - арендован VDS-сервер
   - настроен `Nginx`
   - запросы с домена `prohatalk.ru/api` проксируются на VDS
   - организовано взаимодействие между VDS и локальным сервером через `FRPS` и `FRPC`
   - обработка запросов выполняется локальным сервером

6. Настроено защищённое соединение:

   - получен SSL-сертификат через `Certbot`
   - настроены `HTTPS` и `WSS`
   - SSL интегрирован в `Nginx`

7. Проведена миграция БД сообщений:

   - добавлен флаг `isText`
   - добавлен флаг `isAudio`
   - добавлен флаг `isPicture`

   Флаги используются для определения типа пользовательского сообщения.

8. Усилена безопасность приложения:

   - для REST API настроен `enableCors`
   - вместо `origin: "*"` используется список разрешённых доменов
   - включён режим `credentials: true`
   - для WebSocket-соединений в production-режиме также используется `credentials: true`
   - настройка списка разрешённых `origin` для WebSocket будет завершена в следующем обновлении

9. Проведена оптимизация кода.

# Версия 0.6

1. Добавлен функционал записи времени выхода пользователя из аккаунта:

    - улучшена поддерживаемость проекта
